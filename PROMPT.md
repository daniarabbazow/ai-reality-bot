# ТЗ: Telegram-бот «AI REALITY» — игра «Real или AI?»

Сделай Telegram-бота на Python. Игрок выбирает категорию, затем уровень, и бот по одной присылает картинки. Под каждой две кнопки: **Real** (фото сделал человек) и **AI** (сгенерировано нейросетью). В конце уровня бот показывает, сколько ответов верных.

Все картинки и разметка уже лежат в этой папке. Код пиши так, чтобы новые категории, уровни и картинки добавлялись **только правкой `content.json`**, без изменения кода.

---

## 1. Стек

- Python 3.11+
- aiogram 3.x
- python-dotenv (токен из `.env`)
- SQLite через `aiosqlite` (логирование ответов)
- Хранение состояния игры: aiogram FSM с `MemoryStorage` (этого достаточно для pet-проекта)

## 4. Сценарий игры

### 4.1. Старт
Команда `/start` (и `/menu`) → приветствие и выбор категории:

> 👋 Привет! Это **AI REALITY** — игра, где нужно отличить фото, сделанное человеком, от картинки нейросети.
> Выбери категорию:

Inline-кнопки: по одной на каждую категорию из `content.json` (сейчас только «🌿 Природа»).

### 4.2. Выбор уровня
После нажатия на категорию — **отредактировать** это же сообщение:

> 🌿 Природа
> Выбери уровень:

Кнопки: по одной на каждый уровень (`title` из JSON), все уровни открыты сразу, без блокировок. Последняя кнопка: «⬅️ К категориям».

### 4.3. Прохождение уровня
- Бот присылает первую картинку методом **`send_photo`** (не `send_document`!), чтобы имя и формат файла не были видны игроку.
- Подпись к фото: `Фото 1/5`.
- Под фото две inline-кнопки в один ряд: **«🧑 Real»** и **«🤖 AI»**.
- После нажатия любой кнопки:
  1. засчитать ответ (верно / неверно), записать его в БД;
  2. **убрать кнопки** у этого фото (`edit_reply_markup(reply_markup=None)`), чтобы нельзя было ответить дважды;
  3. **не показывать**, верен ли ответ;
  4. сразу прислать следующую картинку с подписью `Фото 2/5` и теми же кнопками.
- На callback всегда вызывать `callback.answer()`, чтобы у кнопки не висели «часики».

### 4.4. Итог уровня
После ответа на последнюю картинку бот присылает сообщение:

> 🏁 Уровень 1 · лёгкий пройден!
> Верных ответов: **3 из 5**

Кнопки зависят от результата:

**Если не все ответы верные:**
- «🔁 Пройти заново» — начать этот же уровень с первой картинки;
- «➡️ К следующему уровню» — сразу начать следующий уровень этой категории;
- «📂 Вернуться к категориям» — показать выбор категорий (как после `/start`).

**Если все ответы верные:**
- текст дополнить строкой «🎉 Идеально! Ни одной ошибки.»;
- кнопки: «➡️ К следующему уровню» и «📂 Вернуться к категориям» (без «Пройти заново»).

**Если это последний уровень категории:**
- кнопку «➡️ К следующему уровню» не показывать;
- добавить строку «Это был последний уровень в категории — скоро добавим новые!».

## 5. Состояние игры и защита от ошибок

Хранить в FSM для каждого пользователя:
- `session_id` — короткий случайный id текущего прохождения (например, 6 символов);
- `category_id`, `level`;
- `index` — номер текущей картинки;
- `correct` — счётчик верных ответов.

Callback data делать через `CallbackData`-фабрики aiogram 3 (до 64 байт). В callback ответа передавать `session_id` и `index`.

Обработать краевые случаи:
- **Старая кнопка.** Если пришёл ответ с чужим `session_id` или `index` (игрок нажал кнопку на старом фото или из прошлой игры) — `callback.answer("Эта игра уже завершена 🙂", show_alert=False)` и ничего не делать.
- **Двойное нажатие.** Тот же `index` второй раз не засчитывать.
- **`/start` посреди уровня** — сбросить состояние и показать категории.
- **Ошибка отправки фото** — залогировать и написать игроку «Не получилось загрузить картинку, попробуй ещё раз», с кнопкой «📂 К категориям».

## 6. База данных (SQLite, файл `bot.db`)

Таблица ответов — нужна, чтобы потом калибровать сложность:

```sql
CREATE TABLE IF NOT EXISTS answers (
  id INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id INTEGER NOT NULL,
  session_id TEXT NOT NULL,
  category_id TEXT NOT NULL,
  level INTEGER NOT NULL,
  item_id TEXT NOT NULL,
  user_answer TEXT NOT NULL,      -- 'real' | 'ai'
  is_correct INTEGER NOT NULL,    -- 0 | 1
  response_time_sec REAL,         -- от отправки фото до нажатия кнопки
  created_at TEXT NOT NULL DEFAULT (datetime('now'))
);
```

Таблица кэша `file_id`: после первой отправки картинки сохранять `file_id`, который вернул Telegram, и дальше отправлять по нему, а не загружать файл заново.

```sql
CREATE TABLE IF NOT EXISTS photo_cache (
  item_id TEXT PRIMARY KEY,
  file_id TEXT NOT NULL
);
```

Время отправки фото хранить в FSM, чтобы посчитать `response_time_sec`.

## 7. Конфигурация и безопасность

- Токен только в `.env`: `BOT_TOKEN=...`. Создай `.env.example` с пустым значением.
- `.env` и `bot.db` — в `.gitignore`.
- Никогда не выводить токен в логи.
- Логирование через стандартный `logging`, уровень INFO.

5. Как посмотреть статистику: пример SQL-запроса, который показывает долю верных ответов по каждой картинке:
   ```sql
   SELECT item_id, COUNT(*) AS answers, ROUND(AVG(is_correct) * 100) AS pct_correct
   FROM answers GROUP BY item_id ORDER BY item_id;
   ```
